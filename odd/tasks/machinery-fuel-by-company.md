## Specs
- S1 — User: "Todo CUU08 (R018–R021)". Check registration of fuel, maintenance, repair, usage, accumulated hours/hectares and maintenance alerts through public interfaces. Source: `doc/specs/maquinaria-combustible/spec.md` and `doc/casos-de-uso/CUU08-registrar-actividades-sobre-maquinaria.md`.
- S2 — User: "Consolidado y desglose"; "Solo ADMIN con membresía". Check cross-company reads include only authorized memberships and non-admin reads stay on active company; reject unauthorized writes with unchanged data.
- S3 — User: "Dos movimientos separados"; "Compras menos consumos"; "Tratarlos como ingresos". Check purchases and consumption separately; balance = purchases minus consumption per company; old COMBUSTIBLE rows remain intact and count as income. Verify historical balance caveat.
- S4 — User: "Operario y administrativos"; "No hay máquinas compartidas". Check permitted role/type combinations and prohibit cross-company machine access with unchanged data.
- S5 — User: "Archivo adjunto"; "Uno, sin reemplazo (recomendado)"; "Puede adjuntarse después". Check one immutable PDF or image receipt per movement, authorized upload/download, allow income without file as pending, and reject malformed, duplicate or foreign association without writes.
- S6 — User: "Por tipo de máquina"; "ADMIN configura; sin valores por defecto"; "todo el uso corresponde a una tarea"; "Sí, adaptar móvil junto con backend (recomendado)"; "Sincronizar offline; habilitar OPERARIO asignado (recomendado)"; "Conservar fecha y observaciones (recomendado)". Check thresholds by type, no alert before configuration and alert when accumulated hours or hectares meets a configured limit; only ADMIN configures. Task-linked usage is the source on backend and mobile; offline retries must not duplicate usage; OPERARIO may submit only their assigned task usage. A task usage keeps its captured work date and notes; historical standalone rows stay untouched.
- S7 — User: "en la tarea de notion describi de manera breve y sumple el trabajo que vamos a realizar y las decisiones que tomamos para que otros devs estem al tanto." Check readable Notion description and status; do not claim implementation complete before checks.
- S8 — User: "inica a trabajar en el worktree con odd". Check branch/worktree isolation, synced ODD file/mirror/todo, tests and coherent work-unit commits without push/PR.
- S10 — Architect contract for T10: `Machine.type` is a nullable free-text label (no fixed enum) so each firm can use its own machine families. `MaintenanceThreshold` is per `(companyId, machineType)` with optional positive `hoursLimit` and `hectaresLimit`; at least one is required. ADMIN/SUPERVISOR edit thresholds, ADMIN-only configure per S6; reads are company-scoped. `GET /machines/alerts` returns, per firma machine, accumulated `usageHours`/`hectares` summed from `MachineUsage`, the configured limits and `due: true` plus the reasons (`HOURS`, `HECTARES`) only when a configured limit is reached; with no threshold configured there is never an alert.
- S11 — Architect contract for T5: `GET /machine-reports/consolidated` is ADMIN-only and returns one row per company where the caller has membership (`UserCompany`), with `companyId`, `companyName`, `fuelPurchasedLiters`, `fuelConsumedLiters`, `fuelBalanceLiters`, `usageHours`, `hectares`, `maintenanceCost`, `repairCost`, plus a `totals` object. Companies without membership never appear; a non-ADMIN gets 403. Fuel history: `COMBUSTIBLE`/NULL counts as purchased; `CONSUMO` as consumed.
- S12 — Architect contract for T6: the web machinery panel must stop summing `MachineActivity.usageHours` for accumulated usage and read `GET /machine-usages` instead, showing legacy activities only as history (never added to the same total). It also shows task-linked usage detail (task, work date, hours, hectares, notes), `GET /machines/alerts` with the threshold that triggered each alert, an ADMIN-only threshold editor over `GET/PUT/DELETE /maintenance-thresholds`, and — for ADMIN — the `GET /machine-reports/consolidated` table with per-company breakdown and totals. Registering fuel/maintenance/repair keeps using `POST /machine-activities`; registering usage keeps using `POST /machine-usages`.
- S9 — Architect decision (T14 blocker): `GET /companies` is ADMIN/SUPERVISOR only, so an OPERARIO cannot populate the local company row that machines reference. Add an additive, role-safe read `GET /catalog/field` for ADMIN, SUPERVISOR and OPERARIO that returns only the caller's firma (`companies`), tenant clients/farms/lots/laborTypes, firma machines and tenant tasks with their operator ids. Mobile upserts in FK order (companies → clients → farms → lots → laborTypes → machines → tasks → taskOperators) and labels tasks with lot/labor names.
